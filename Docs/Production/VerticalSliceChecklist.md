# 버티컬 슬라이스 체크리스트

이 파일은 위에서 아래로 하나씩 끝내기 위한 작업 순서입니다. 한 항목을 끝낼 때마다 에디터에서 확인하고 체크합니다.

## 현재 진행 위치와 실행 순서

- 완료 게이트: `0. 현재 기준 정리`, `1. 씬 흐름 고정`, `2. 입력과 캐릭터 기본감`
- 현재 작업 게이트: `3. 회색 박스 근접 전투`
- 현재 P0: 필요한 전투 클립 확정 -> GAS 전투 기반 -> 기본 공격 골든 히트 -> 패리/스태미나 고갈 -> 기회공격
- 이후 순서: 적 무리 -> 신성한 계율/금단 기술 -> 처형/회복 -> 최소 UI/미션 흐름

완료된 게이트는 명시적인 회귀 버그가 발견되지 않는 한 다시 작업 목록에 올리지 않습니다. 이동 속도와 애니메이션 전환 같은 미세 조정도 버티컬 슬라이스 진행을 막는 수준이 아니면 완료 게이트를 되돌리는 이유로 삼지 않습니다.

## 0. 현재 기준 정리

- [x] 게임 방향 문서에 `신성한 계율 = 신성력 기반 정공법`, `금단 기술 = 패턴 파괴 도구` 규칙을 반영한다.
- [x] 어둠의 형상은 금단 기술 슬롯 4개와 별도인 5번째 금단 계열 입력으로 분리한다.
- [x] Boot 맵에서 바닥, 조명, PlayerStart 같은 테스트용 액터를 제거한다.
- [x] 테스트용 바닥 패드는 `Content/80_Dev/TestMaps/L_OpenWorldTestArena`로 옮긴다.
- [x] 외부 에셋은 `Content/90_ExternalAssets/Marketplace` 아래로 모으고, 옛 `Polyart` / `StarterContent` 잔여 파일을 치운다.

## 1. 씬 흐름 고정

- [x] Boot 맵에는 플레이어, 바닥, 적, 테스트 조명, 임시 UI를 두지 않는다.
- [x] Boot 맵의 역할을 `GameInstance`, Subsystem, Asset Manager 초기화와 첫 미션 로딩으로 제한한다.
- [x] 실제 플레이 테스트는 `Content/80_Dev/TestMaps/L_OpenWorldTestArena`에서 진행한다.
- [x] 첫 버티컬 슬라이스까지는 `L_OpenWorldTestArena`를 플레이 공간으로 사용하고, 별도 `L_VerticalSlice_Arena` 분리는 미션 흐름을 만들 때 다시 결정한다.

## 2. 입력과 캐릭터 기본감

- [x] `IMC_Gameplay`와 `IA_*` 입력 에셋을 기준 입력으로 둔다.
- [x] `BP_ZorbaCharacter`에서 모든 `Zorba|Input` 액션이 연결되어 있는지 확인한다.
- [x] 패드 기준 이동, 카메라, 회피, 어둠의 형상, 달리기 토글을 테스트한다.
- [x] `LT + A/B/X/Y`가 금단 기술 슬롯 1~4 요청 로그로 들어오는지 확인한다.
- [x] 키보드/마우스에서도 같은 의도 이름으로 동작하는지 확인한다.

## 3. 회색 박스 근접 전투

### 전투 사전준비: 클립 게이트

현재 플레이어 기준은 `SK_Garret_FullBody`와 `ABP_ZorbaPlayer`이며, 기존 `RTG_Zorba_Unarmed` 경로처럼 Manny 계열 소스를 Polyart 캐릭터로 리타깃할 수 있어야 합니다. 아직 약한 적의 기준 메시와 스켈레톤이 없으므로, 클립을 고르기 전에 P0 적도 같은 Polyart `SKEL_Mannequin` 계열을 사용할지 먼저 확정합니다.

모든 클립을 한꺼번에 기다리지 않습니다. 각 구현 게이트에 들어가기 전에 해당 묶음만 확정합니다.

| 진입 게이트 | 필요한 클립 | 최소 조건 |
| --- | --- | --- |
| A. 기본 공격 골든 히트 | 플레이어 기본 공격, 적 기본 공격, 플레이어 패리, 플레이어/적 정면 피격, 적 패리 반응 | 공격은 준비/접촉/회수 구간이 분명하고, 피격과 패리 반응은 큰 위치 이동 없이 짧게 복귀 |
| B. Exhausted와 기회공격 | 적 Exhausted 진입/유지/회복, 기회공격 공격자/피격자 한 쌍 | 고갈과 회복이 즉시 읽히며, 동기화 한 쌍은 같은 기준 시점과 상대 거리로 제작 |
| C. 라이프사이클 승인 | 플레이어/적 방향 무관 사망 | 사망 상태 진입과 충돌 해제를 가릴 정도의 과도한 이동이 없음 |
| P1 확장 | 플레이어 강공격, 적 방어 반응 | 기본 공격보다 긴 준비와 큰 스태미나 피해, 방어 성공이 명확히 읽힘 |
| 이후 | 방향별 피격, 처형 공격자/피격자 한 쌍 | 기본 전투 골든 히트 승인 뒤 확장 |

현재 P0 후보는 A 6개, B 5개, C 2개로 총 13개입니다. A만 확정하면 GAS 기반과 기본 타격 구현은 시작할 수 있고, B를 확보하기 전에는 기회공격의 카메라와 무적 타이밍을 확정하지 않습니다. 공격 클립에는 판정 시작/종료와 접촉 Notify를 놓을 수 있어야 하며, 동기화 클립은 두 캐릭터를 독립적으로 미끄러뜨려 맞추지 않습니다.

### 구현 순서

- [ ] `GameplayAbilities`, `GameplayTags`, `GameplayTasks` 기반과 공용 Attribute/Tag 계약을 만든다.
- [ ] 체력, 전투 스태미나, 신성력과 사망/Exhausted 상태를 만든다.
- [ ] 전용 근접 Trace/Hurtbox 충돌 계약과 팀 필터를 만든다.
- [ ] 공격별 전방 보정 범위와 무기 소켓 Sweep을 결합한 기본 공격 1타를 만든다.
- [ ] 공격 성공, 빗나감, 피격과 동일 대상 중복 방지를 확인한다.
- [ ] 적 공격 비용과 패리의 큰 스태미나 피해, 고갈 후 Exhausted/회복 흐름을 만든다.
- [ ] Exhausted 마커, 기본 공격 기회공격 전환, 카메라 연출, 제한된 무적과 취소 정리를 만든다.
- [ ] 강공격 1타와 약공격 후 강공격 파생을 받을 콤보 단계 기록을 만든다.
- [ ] 방어 상태와 패리 판정창을 완성한다.
- [ ] 회피와 어둠의 형상의 이동 속도, 충돌 규칙, 지속시간, 쿨다운을 분리한다.
- [ ] 가까운 적을 향한 약한 소프트 유도를 붙인다.

## 4. 적 무리 프로토타입

- [ ] 약한 적 1종을 공용 GAS 전투 계약 위에 만든다.
- [ ] 적이 플레이어에게 접근하고, 스태미나를 소비해 짧은 근접 공격을 하게 한다.
- [ ] 적 피격 반응과 짧은 경직을 만든다.
- [ ] 테스트 아레나에 3~5마리 소규모 무리 스폰을 배치한다.
- [ ] 둘러싸였을 때 카메라와 이동이 답답하지 않은지 확인한다.

## 5. 신성한 계율과 금단 기술

- [ ] 신성력을 소모하는 신성한 계율 1개를 만든다. 예: 패리 후 적의 전투 스태미나를 크게 깎는 반격.
- [ ] 금단 기술 1개를 만든다. 예: 광폭화나 특수 상태를 강제로 끊는 패턴 파괴기.
- [ ] 신성한 계율은 방어, 패리, 회피, 강공격 같은 기본 공방 입력 위에 붙는지 확인한다.
- [ ] 금단 기술은 쿨다운 또는 충전 횟수로 제한한다.
- [ ] 금단 기술은 일반 피해 기술보다 특정 적 패턴을 깨는 도구로 먼저 검증한다.

## 6. 처형과 회복 루프

- [ ] 전투 스태미나와 무관하게 적 체력이 낮아지면 처형 가능 상태를 표시한다.
- [ ] `ContextAction`이 가능한 경우 처형을 우선 선택하게 한다.
- [ ] 처형 중 짧은 안전 시간을 준다.
- [ ] 처형으로 체력 또는 신성력을 회복한다.
- [ ] 기회공격은 연출 중 제한된 무적만 주고, 종료 후에는 처형의 체력/신성력 회복이나 추가 안전 시간을 주지 않는지 확인한다.
- [ ] 적이 많을수록 처형 타이밍을 찾는 리듬이 생기는지 테스트한다.

## 8. 검증과 작업 규칙

아래 항목은 완료해야 닫히는 작업이 아니라 전체 제작 기간에 적용하는 운영 규칙입니다.

- 에디터가 열려 있으면 전체 C++ 빌드를 돌리지 않는다.
- C++ 헤더나 UHT 대상 변경 전에는 에디터에서 저장하고 에디터를 닫는다.
- 에디터를 닫은 뒤 `Build.bat ZorbaEditor Win64 Development`로 빌드한다.
- 에디터가 열린 상태에서 해야 한다면 MCP로 맵, 에셋, 로그 검증만 진행한다.
- 작은 `.cpp` 구현 변경만 Live Coding으로 확인하고, 헤더/생성 코드 변경은 정식 빌드로 확인한다.
- 각 단계 끝에서 Output Log, PIE 플레이, git diff를 확인한다.
