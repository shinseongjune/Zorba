# 버티컬 슬라이스 체크리스트

이 파일은 위에서 아래로 하나씩 끝내기 위한 작업 순서입니다. 한 항목을 끝낼 때마다 에디터에서 확인하고 체크합니다.

## 0. 현재 기준 정리

- [x] 게임 방향 문서에 `신성한 계율 = 신성력 기반 정공법`, `금단 기술 = 패턴 파괴 도구` 규칙을 반영한다.
- [x] 어둠의 형상은 금단 기술 슬롯 4개와 별도인 5번째 금단 계열 입력으로 분리한다.
- [x] Boot 맵에서 바닥, 조명, PlayerStart 같은 테스트용 액터를 제거한다.
- [x] 테스트용 바닥 패드는 `Content/80_Dev/TestMaps/L_OpenWorldTestArena`로 옮긴다.
- [x] 외부 에셋은 `Content/90_ExternalAssets/Marketplace` 아래로 모으고, 옛 `Polyart` / `StarterContent` 잔여 파일을 치운다.

## 1. 씬 흐름 고정

- [ ] `Content/00_Core/Maps/L_Boot`를 기본 시작 맵으로 유지한다.
- [ ] Boot 맵에는 플레이어, 바닥, 적, 테스트 조명, 임시 UI를 두지 않는다.
- [ ] Boot 맵의 역할을 `GameInstance`, Subsystem, Asset Manager 초기화와 첫 미션 로딩으로 제한한다.
- [ ] 실제 플레이 테스트는 `Content/80_Dev/TestMaps/L_OpenWorldTestArena`에서만 진행한다.
- [ ] 첫 플레이용 미션 맵 후보를 `Content/20_World/Maps/L_VerticalSlice_Arena`로 만들지 결정한다.

## 2. 입력과 캐릭터 기본감

- [x] `IMC_Gameplay`와 `IA_*` 입력 에셋을 기준 입력으로 둔다.
- [ ] `BP_ZorbaCharacter`에서 모든 `Zorba|Input` 액션이 연결되어 있는지 확인한다.
- [ ] 패드 기준 이동, 카메라, 회피, 어둠의 형상, 달리기 토글을 테스트한다.
- [ ] `LT + A/B/X/Y`가 금단 기술 슬롯 1~4 요청 로그로 들어오는지 확인한다.
- [ ] 키보드/마우스에서도 같은 의도 이름으로 동작하는지 확인한다.

## 3. 회색 박스 근접 전투

- [ ] 기본 공격 1타 임시 판정을 만든다.
- [ ] 강공격 1타 임시 판정을 만든다.
- [ ] 약공격 후 강공격 파생을 받을 수 있도록 콤보 단계 기록을 만든다.
- [ ] 방어 또는 패리 상태를 만든다.
- [ ] 회피와 어둠의 형상의 이동 속도, 충돌 규칙, 지속시간, 쿨다운을 분리한다.
- [ ] 가까운 적을 향한 약한 소프트 유도를 붙인다.
- [ ] 공격 성공, 빗나감, 피격 로그를 Output Log에서 확인한다.

## 4. 적 무리 프로토타입

- [ ] 약한 적 1종을 만든다.
- [ ] 적이 플레이어에게 접근하고 짧은 근접 공격을 하게 한다.
- [ ] 적 피격 반응과 짧은 경직을 만든다.
- [ ] 테스트 아레나에 3~5마리 소규모 무리 스폰을 배치한다.
- [ ] 둘러싸였을 때 카메라와 이동이 답답하지 않은지 확인한다.

## 5. 신성한 계율과 금단 기술

- [ ] 신성력을 소모하는 신성한 계율 1개를 만든다. 예: 패리 후 자세 피해가 큰 반격.
- [ ] 금단 기술 1개를 만든다. 예: 광폭화나 특수 상태를 강제로 끊는 패턴 파괴기.
- [ ] 신성한 계율은 방어, 패리, 회피, 강공격 같은 기본 공방 입력 위에 붙는지 확인한다.
- [ ] 금단 기술은 쿨다운 또는 충전 횟수로 제한한다.
- [ ] 금단 기술은 일반 피해 기술보다 특정 적 패턴을 깨는 도구로 먼저 검증한다.

## 6. 처형과 회복 루프

- [ ] 적 체력이 낮아지면 처형 가능 상태를 표시한다.
- [ ] `ContextAction`이 가능한 경우 처형을 우선 선택하게 한다.
- [ ] 처형 중 짧은 안전 시간을 준다.
- [ ] 처형으로 체력 또는 신성력을 회복한다.
- [ ] 적이 많을수록 처형 타이밍을 찾는 리듬이 생기는지 테스트한다.

## 7. 최소 UI와 미션 흐름

- [ ] 임시 시작 화면 또는 바로 미션 시작 흐름을 만든다.
- [ ] 일시정지 메뉴를 만든다.
- [ ] 체력, 신성력, 금단 기술 쿨다운을 임시 UI로 표시한다.
- [ ] 미션 성공/실패 조건을 만든다.
- [ ] 성공/실패 후 Boot 또는 시작 흐름으로 돌아오게 한다.

## 8. 검증과 작업 규칙

- [ ] 에디터가 열려 있으면 전체 C++ 빌드를 돌리지 않는다.
- [ ] C++ 헤더나 UHT 대상 변경 전에는 에디터에서 저장하고 에디터를 닫는다.
- [ ] 에디터를 닫은 뒤 `Build.bat ZorbaEditor Win64 Development`로 빌드한다.
- [ ] 에디터가 열린 상태에서 해야 한다면 MCP로 맵, 에셋, 로그 검증만 진행한다.
- [ ] 작은 `.cpp` 구현 변경만 Live Coding으로 확인하고, 헤더/생성 코드 변경은 정식 빌드로 확인한다.
- [ ] 각 단계 끝에서 Output Log, PIE 플레이, git diff를 확인한다.
