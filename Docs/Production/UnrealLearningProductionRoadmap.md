# Unreal 학습·Zorba 제작 로드맵

이 문서는 Zorba를 실제로 제작하면서 Unreal Engine을 독립적으로 다룰 수 있게 되는 하루 단위 학습 순서를 관리합니다. 무엇을 만들지는 [VerticalSliceChecklist.md](VerticalSliceChecklist.md)가 결정하고, 이 문서는 그 작업을 어떤 학습 순서와 역할 분담으로 수행할지를 결정합니다.

목표는 Unreal의 모든 기능을 암기하는 것이 아니라, **Zorba 규모의 싱글 플레이 버티컬 슬라이스를 혼자 설계·제작·진단·패키징할 수 있는 실전 자립**입니다. Unity 경험은 전제로 두며 `Actor`, `Component`, Transform, 씬 편집처럼 이미 아는 개념을 반복해서 소개하지 않습니다. Unreal 고유의 소유 구조, 에셋 파이프라인, 도구 사용법과 Zorba의 실제 호출 경로만 필요한 깊이까지 다룹니다.

## 현재 위치

- 마지막 갱신: 2026-09-06
- 현재 제작 게이트: 캐릭터·애니메이션 제품 파이프라인
- 완료한 학습일: `D01–D06`
- 다음 학습일: `D07 — Marketplace 원본, 프로젝트 소유 에셋, 파생 에셋의 경계 익히기`
- `D01`은 사용자의 기존 Unity 경험, 에디터 재실행, `L_M01_Graybox` 탐색과 기본 편집·PIE·저장/Undo 숙련 확인으로 통과했습니다.
- `D02`는 사용자가 Data Asset, Reference Viewer, Level/Outliner, World Settings, Project Settings와 실제 C++ 선언·구현을 직접 추적하고 미션 데이터·맵 전환 인계·조우 완료·GameMode 판정·GameState 통지의 책임을 자신의 말로 구분해 통과했습니다.
- `D03`은 사용자가 Boot 시작, 성공, 재시작 복원, 의도적 실패와 Boot 복귀를 직접 PIE로 확인하고, 즉시 적 접촉을 최우선 공간 문제로 좁혔으며 적 역할과 성공·실패 결과 가독성은 통과로 판정했습니다.
- `D04`는 사용자가 측정 도구로 시작 거리 190cm를 확인하고 `PlayerStart`를 이동했으며, 이동을 막던 불필요한 바닥 단차를 제거했습니다. 사용자 PIE에서 약 9초 접근, 직진 방향 가독성, 3+1 적의 재시작 복원과 장시간 막힘 없음을 확인했고, 테스트용 그레이박스에는 추가 성문·안뜰 장식을 만들지 않기로 결정했습니다.
- `D05`는 사용자가 조우의 남은 적 수 델리게이트, PlayerController의 단계별 구독·해제, 위젯의 Blueprint 읽기 함수와 Slate 진행 패널을 직접 구현했습니다. 사용자가 `Development Editor / Win64` 정식 빌드 성공을 보고했고, 사용자 PIE에서 목표·초기 적 수 4·처치에 따른 감소·성공 화면 전환, 재시작 시 4로 복원 및 재갱신, 실패 화면·Boot 복귀를 모두 정상으로 확인했습니다. 이번 완료 증거는 사용자 빌드 보고와 사용자 PIE이며, 별도 자동화·패키지 실행 검증은 수행하지 않았습니다.
- `D06`은 사용자가 네이티브 Slate 표시를 `WBP_MissionFlow`의 UMG Designer/Graph로 이전하고, 앵커·진행/결과 상태·버튼 라우팅·패드 포커스를 직접 구성했습니다. `Development Editor / Win64` 정식 빌드와 사용자 PIE에서 Boot→M01, 적 수 4→0, 성공, 재시작 시 4 복원, 실패, Boot 복귀, 패드 탐색·확정을 모두 통과했으며 로그로 전체 단계 전환을 교차 확인했습니다.

## 매 세션 운영 규칙

1. 작업 시작 시 이 문서의 `현재 위치`와 [VerticalSliceChecklist.md](VerticalSliceChecklist.md)의 `현재 작업 인계`를 함께 읽습니다.
2. 에이전트는 먼저 현재 Git 상태와 실제 코드·에셋 호출 경로를 읽기 전용으로 확인합니다. 이미 승인된 기능은 회귀 증거가 없으면 다시 열지 않습니다.
3. 에이전트는 핵심 작업 전에 `목적 → 책임 객체 → 바뀌는 것 → 확인 방법 → 되돌리는 방법`을 짧게 설명합니다. Unity와 같은 일반 개념이나 당일 목표와 무관한 임시 클래스는 해설하지 않습니다.
4. 핵심 에디터 조작과 학습용 구현은 사용자가 직접 수행합니다. 에이전트는 기본적으로 경로 안내, 코드 리뷰, 진단과 검증을 담당하며, 사용자가 명시적으로 위임한 경우에만 대신 변경합니다.
5. 한 학습일은 보통 45~120분입니다. 완료 조건을 충족하지 못하면 다음 번호로 넘어가지 않고 같은 날을 이어갑니다. 반대로 이미 숙련된 항목은 직접 수행 증거를 확인한 뒤 합치거나 건너뛸 수 있습니다.
6. 매일 실제 게임 산출물 또는 재사용 가능한 검증 결과를 하나 남깁니다. 연습용 에셋은 `80_Dev` 또는 별도 스테이징 맵에 두고, 승인된 것만 제품 폴더로 승격합니다.
7. 종료 시 사용자 체감 PIE, 정식 빌드, 자동화, 패키지 실행을 서로 구분해 기록합니다. 체크박스와 `현재 위치`를 갱신하고, 제작 게이트가 변한 경우에만 체크리스트 인계를 갱신합니다.
8. 커밋·푸시는 별도 요청이 있을 때만 수행합니다. Marketplace 원본과 `Config/DefaultEditor.ini` 같은 사용자·에디터 변경을 보호하고 명시적 경로만 스테이징합니다.
