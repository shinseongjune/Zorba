# 조작과 입력

## 설계 원칙

Zorba의 조작은 **패드 우선**으로 설계하고, 그 다음 키보드/마우스로 옮깁니다.

키보드/마우스는 버튼 수가 많아 기능이 늘어도 흡수하기 쉽습니다. 반대로 패드는 초반에 편하지 않으면 게임 구조 자체가 불편해집니다.

입력의 기준은 하나로 둡니다.

- 물리 키 배치: `IMC_Gameplay` Enhanced Input 에셋
- 입력 액션 에셋: `IA_*`
- 기본 스폰 경로: `BP_ZorbaGameMode -> BP_ZorbaCharacter`
- 행동 처리: C++ `ZorbaCharacter`
- `DefaultInput.ini`: Enhanced Input을 쓰기 위한 엔진 설정만 유지

즉, 키를 바꾸거나 프리셋을 만들 때는 `DefaultInput.ini`나 C++에 키 이름을 추가하지 않고 `IMC_Gameplay`와 이후 입력 설정 UI를 통해 바꿉니다.

## 전투 액션 모델

Zorba는 "기술을 하나씩 넘긴 뒤 사용 버튼을 누르는 방식"이 아니라, **금단 기술 슬롯 4개를 직접 누르는 방식**을 기본으로 합니다.

플레이어는 캐릭터별 고정 금단 기술 4개와 별도 이동 기술인 어둠의 형상을 가집니다. 그래서 금단 계열 입력은 총 5개입니다.

- 금단 기술 슬롯 1
- 금단 기술 슬롯 2
- 금단 기술 슬롯 3
- 금단 기술 슬롯 4
- 어둠의 형상

신성한 계율은 방어, 패리, 회피, 강공격처럼 정공법 공방을 담당합니다. 별도 신성력 자원은 두지 않고 비용이 필요하면 공용 `CombatStamina`를 사용합니다. 금단 기술은 적의 불합리한 패턴이나 특수 상태를 깨는 강한 도구이며, 첫 버전에서는 넓은 빌드 조합을 목표로 하지 않습니다.

첫 신성한 계율은 새 버튼을 추가하지 않는 후방 공격 패시브입니다. 피격자 후방축 기준 ±60도 안에서 가한 플레이어 근접 공격은 전방 유지 방어와 정면 전용 피해 경감을 무시하고 체력 피해가 `1.5배`가 됩니다. 전투 스태미나/자세 피해는 원본 값을 유지하고 확정 사망 처형은 배율 대상에서 제외합니다. 별도 자원 비용은 없으며, 후방 판정과 피해 수정은 이후 정면 피해 경감형 적도 함께 사용할 공용 방향 판정 계약으로 구현합니다. 패리 직후 강공격 강화는 기존 패리 보상을 중복 강화하므로 첫 계율에서 제외합니다.

신성한 계율과 금단 기술은 실력 단계로 나뉘지 않습니다. 신성한 계율만으로는 위험하거나 파훼가 어려운 적 패턴이 있고, 그런 순간에 금단 기술을 능동적으로 써서 패턴을 부숩니다.

### 전투 상태별 입력 우선순위

| 대상 상태 | 입력 | 결과 |
| --- | --- | --- |
| 일반 | `PrimaryAttack` | 기본 공격 |
| `Exhausted`이며 기회공격 범위 안 | `PrimaryAttack` | 기회공격 |
| 체력이 처형 기준 이하 | `ContextAction` | 처형 |
| `Exhausted`이면서 처형 가능 | `PrimaryAttack` / `ContextAction` | 기회공격 / 처형을 입력별로 선택 |

체력은 사망과 처형만 결정합니다. 플레이어의 기본 공격은 무료이고 강공격·회피·신성한 계율과 방어 충격이 `CombatStamina`를 사용합니다. 고갈된 플레이어는 강한 행동을 제한받지만 기회공격 대상이 되지 않습니다. P0 기본 적은 공격 비용을 내지 않으며, 패리와 강한 공격으로 스태미나가 0이 되면 `State.StaminaDepleted`와 함께 `State.Exhausted`에 들어가 기회공격 창을 엽니다. 기회공격은 마커 표시, 카메라 전환, 플레이어가 통제권을 잃는 구간의 무적을 하나의 행동으로 관리합니다.

### 적 전투 등급과 패리 결과

| 적 등급 | 패리 결과 | 후속 흐름 |
| --- | --- | --- |
| `Fodder` | 즉결처형으로 즉시 사망 | 처형 회복과 짧은 제한 무적 발동, 쌍 Montage·카메라 고정 없음 |
| `Elite` | 공격 중단, 전투 스태미나 피해, 짧은 경직 | 스태미나 고갈 뒤 기회공격 또는 체력 저하 뒤 처형 |
| `Boss` | 역할별 데이터로 별도 정의 | 졸개 즉결 규칙을 자동 상속하지 않음 |

졸개 패리 즉결은 긴 쌍 연출 대신 전투 흐름 안에서 바로 끝나는 **즉결처형**입니다. 성공하면 `DA_Player_Execution01`의 처형 회복량을 그대로 적용하고, 같은 Data Asset의 `InstantExecutionInvulnerabilityDuration` 동안 제한 무적을 얻습니다. 사망은 일반 피해와 같은 `Health → State.Dead → OnEnemyDied` 경로를 사용하므로 전멸 판정과 군중 공격 토큰이 별도 예외 없이 정리됩니다. 나중에 짧은 반격 모션과 피격 반응을 `OnParryInstantKill` Blueprint 이벤트에 붙일 수 있지만, 현재 판정·회복·무적·사망·조우 완료 로직은 모션 유무와 독립적입니다.

군중전에서는 적별 피격·패리·탈진·사망 상태를 각 액터가 소유하고, 월드 군중 조정자는 둘러싸기 위치와 동시 근접 공격권만 관리합니다. 현재 P0 상한은 한 번에 공격자 1명이며, 나머지는 플레이어 주변의 안정된 슬롯으로 이동합니다. 패리 유도·회피 전용·장거리 기습처럼 별도 대응을 요구하는 공격은 일반 공격권과 별개의 `특수 신호권`을 사용하므로 한 플레이어에게 둘 이상이 동시에 특별 대응을 요구하지 않습니다.

### 최소 적 AI 책임 계약

현재 적 AI는 Behavior Tree/StateTree 완성본이 아니라 `UZorbaEnemyCombatBrainComponent`의 작은 상태 흐름입니다. Brain은 대상 선택, 관찰 행동, 이동 의도, 공격 선택만 담당하고 `UZorbaEnemyBasicAttackComponent`는 선택된 Attack Definition의 실행기, `UZorbaMeleeCombatComponent`는 Montage·Notify·타격 판정 실행기로 남습니다. 나중에 AI Perception, NavMesh 경로 탐색, Behavior Tree/StateTree를 도입해도 공격 데이터와 판정 코드를 갈아엎지 않는 경계입니다.

- 관찰은 `Watch`, `Strafe`, `SpecialMotion` 세 행동이며 특수 모션은 Blueprint 이벤트 연결점만 먼저 둡니다.
- 공격 프로필은 교전/이탈 거리, 관찰 거리와 시간, 행동 가중치, 공격별 선택 거리·가중치·재사용 시간·접근 속도, 방어 확률·유지 시간·재사용 시간을 소유합니다.
- 공격을 고르면 실제 HitPhase 사거리까지 접근한 뒤 실행합니다. 장거리 기습은 먼 거리에서만 후보가 되고 더 높은 접근 속도를 사용할 수 있습니다.
- 졸개 프로필은 기본 공격만 사용하고 방어하지 않습니다. 정예 프로필은 기본·패리 유도·회피 전용·장거리 기습과 낮은 빈도의 방어를 사용합니다.

### 방어 상호작용 계약

플레이어와 적은 같은 공격 데이터의 방어 상호작용 값을 해석합니다. 공격별 방어 성질은 `UZorbaAttackDefinition`이 소유하고 다음 세 종류로 분리합니다.

| 공격 성질 | 유지 방어 | 정확한 패리 | 요구 대응 |
| --- | --- | --- | --- |
| 기본형 | 가능 | 가능 | 방어·패리·회피 중 선택 |
| 가드 브레이크형 | 방어 파괴 | 가능 | 패리 또는 회피 |
| 회피 전용형 | 불가능 | 불가능 | 회피 |

플레이어 단독 강공격과 약→강 파생은 가드 브레이크형입니다. 적의 `EnemyParry01`은 정확한 패리는 허용하지만 유지 방어를 깨고, `EnemyDodge01`은 방어와 패리를 모두 무시하며, `EnemyAmbush01`은 먼 거리에서 빠르게 접근하는 기습형입니다. 현재 개발 빌드는 특수 신호권을 얻은 순간 임시 색상 텍스트로 타입을 표시하고 `OnAttackSignalStarted` Blueprint 이벤트를 호출합니다. 최종 GameplayCue/VFX는 이 이벤트에 붙이며, 표현 누락이나 교체가 실제 판정을 바꾸지는 않습니다.

## 패드 기본안

| 의도 | 입력 |
| --- | --- |
| 이동 | 왼쪽 스틱 |
| 카메라 | 오른쪽 스틱 |
| 기본 공격 | RT / R2 |
| 강공격 | RB / R1 |
| 방어 / 패리 | LB / L1 |
| 금단 기술 레이어 | LT / L2 누르고 있기 |
| 금단 기술 1 | LT + A / Cross |
| 금단 기술 2 | LT + B / Circle |
| 금단 기술 3 | LT + X / Square |
| 금단 기술 4 | LT + Y / Triangle |
| 회피 | A / Cross |
| 어둠의 형상 | B / Circle |
| 상호작용 / 처형 | X / Square |
| 캐릭터 액션 / 태세 | Y / Triangle |
| 성유물 / 회복 | D-pad 아래 |
| 목표 표시 | D-pad 위 |
| 달리기 토글 | 왼쪽 스틱 클릭 |
| 일시정지 | Menu / Options |

현재 C++ 입력 처리는 `LT / L2`를 금단 기술 레이어로 기억합니다. 그래서 `LT`를 누른 상태에서 A/B/X/Y를 누르면 기존 회피/어둠의 형상/상호작용/캐릭터 액션 대신 금단 기술 슬롯 1/2/3/4가 요청됩니다.

달리기는 이동 중에만 유효합니다. 이동 중 스프린트 입력을 누르면 토글되고, 이동을 멈추면 자동으로 꺼집니다. 스프린트 입력을 누른 상태로 이동을 시작해도 달리기로 들어갑니다.

회피는 입력 순간의 이동 입력을 카메라 기준 방향으로 사용합니다. 이동 입력이 없을 때는 캐릭터 전방으로 회피합니다.

## 첫 입력 액션 이름

코드와 에셋이 공유할 플레이어 의도 이름입니다.

`UseAbilitySlot1~4`라는 코드 이름은 아직 일반적인 ability 표현을 쓰지만, 디자인 의미는 금단 기술 슬롯입니다. 신성한 계율은 기본 공방 입력 위에 붙습니다.

약공격은 가까운 적을 향한 약한 유도 성능을 갖는 평타입니다. 유효한 `Exhausted` 적이 가까이 있으면 같은 입력이 기회공격을 우선합니다. 강공격은 단독으로도 쓰지만, 약공격 1타 후 강공격, 약공격 2타 후 강공격처럼 연타 흐름 뒤에 붙었을 때 다른 파생으로 확장할 수 있습니다. 어떤 파생이 실제로 가능한지는 애니메이션과 판정 리소스가 준비된 뒤 확정합니다.

```text
Move
Look
PrimaryAttack
HeavyAttack
Defend
Dodge
DarkForm
Sprint
AbilityLayer
ContextAction
ClassAction
UseAbilitySlot1
UseAbilitySlot2
UseAbilitySlot3
UseAbilitySlot4
UseRelic
ShowObjective
Pause
UIConfirm
UIBack
UINavigate
UITabNext
UITabPrev
UIReset
```

첫 슬라이스에서는 미루는 입력입니다.

```text
LockTarget

SwitchWeapon
UseEquipment

Chat

```
